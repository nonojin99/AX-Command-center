# 1. 입력: 불량 관련 메일 → 정리 스키마

메일 한 통을 아래 항목으로 구조화한다. 모르는 값은 `미기재`로 두고 추측하지 않는다.

| 항목 | 설명 | 예시(가상) |
|---|---|---|
| mail_id / 수신시각 | 메일 식별 | M-0001 / 2026-11-18 08:12 |
| 요청 구분 | 신규 불량 / 추가 확인 / 재발 / 문의 | 신규 불량 |
| 제품·공정 | | `<PRODUCT>` / `<PROCESS>` |
| Lot / 수량 | | `<LOT_ID>` / 25 |
| 불량 유형 | 사내 불량 코드 기준 | `<DEFECT_CODE>` |
| 발생 시점·구간 | | |
| 장비·설비 | | `<EQP_ID>` |
| 긴급도 | 메일 표현·고객 영향 기준 (판단 기준표 참조) | |
| 첨부 | 이미지·로그 종류 | |
| 요청 사항 | 보낸 사람이 원하는 것 | |

> 실제 값은 이 파일이 아니라 분석 결과물(outputs/)에도 `<자리표시자>`로 남기거나, 사내 환경에서만 채운다.
