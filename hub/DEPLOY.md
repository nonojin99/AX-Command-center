# 적용·테스트 가이드 (A안: Claude Code 로 자유 질문 분석)

이 묶음은 **새 파일만** 들어 있다 — 기존 파일을 덮어쓰지 않으니 저장소 루트에 그대로 합치면 된다(`hub/`, `.claude/`).

## ⚠ 먼저 확인할 것: 데이터가 Claude 에게 전달된다
이 방식에서는 쿼리 **실행 결과가 Claude(외부 모델)에 전달**된다. 정형 허브(Streamlit)와 달리 "코드만 만들고 데이터는 안 본다"가 아니다.
- **실제 DB(`HUB_SOURCE=bdq`)를 연결하기 전에, 데이터 사용 승인 범위를 확인한다.** 승인 전에는 가상 데이터(기본값)로만 테스트한다.
- 승인이 나더라도 노출을 줄이는 장치: `HUB_PREVIEW_ROWS=0`(행 미표시, 형태·집계만), 전체 표는 `hub/runs/` 파일에만 저장(.gitignore 처리).
- `hub/runs/` 와 실데이터가 든 파일은 커밋·공유하지 않는다.

## 순서
1. **환경 확인 (가상 데이터, 승인 불필요)**
   ```
   python3 hub/tests/test_checks.py            # 점검 모듈
   python3 hub/examples/pm_before_after.py     # 예시 분석 → hub/runs/<시각>_.../summary.md 생성 확인
   ```
   (pandas·numpy 가 필요. `hub/tests/test_engine.py`·Streamlit 은 이전 묶음에 포함)
2. **스킬이 인식되는지 확인** — 저장소에서 Claude Code 를 열고 가상 데이터로 질문:
   `A01 의 최근 PM 전후 7일 결함 수를 비교해줘`
   - 확인: ① CATALOG.md 를 읽었나 ② `Session`·`s.note` 로 가정을 남겼나 ③ `hub/runs/` 에 기록이 생겼나 ④ 답이 `SKILL.md` 의 답변 형식을 따르나
   - 스킬이 인식되지 않으면(사내 버전·설정에 따라 다를 수 있음) `SKILL.md` 본문을 저장소 `CLAUDE.md` 에 붙여 넣어 대체한다.
3. **자유 질문 테스트**: `hub/tests/free_questions.md` 10문항을 가상 데이터로 먼저 돌려 채점. 6·7번(과잉 결론·모호)이 핵심.
4. **카탈로그 채우기** (실제 연결 전 필수): `hub/CATALOG.md` 의 `?` 를 실제 테이블·컬럼·정의로. 최소한 npw, pm, parts 의 조인 키와 'PM 시각의 의미'.
5. **BDQSource 구현** (`hub/engine/sources.py`): `SyntheticSource` 와 같은 메서드·컬럼명으로 DataFrame 반환. 읽기 전용 계정, 파라미터 바인딩, 쿼리 문장을 `self.log` 에 남긴다.
6. **실데이터 테스트** (승인 후): `HUB_SOURCE=bdq HUB_PREVIEW_ROWS=0` 으로 시작. **기존 A·B 툴 결과를 정답지**로 같은 질문을 비교.

## 되돌려 받으면 좋은 것 (실데이터·민감 정보 제외)
- 채점표(어느 질문이 맞고 틀렸나)와 틀린 유형
- `summary.md` 의 **점검 경고**와 가정 목록 (표 csv 는 제외)
- 카탈로그에서 막혔던 질문들 ('PM 시각의 의미', 'W 지표 정의' 같은 것)

## 한계
- `SKILL.md` 가 사내 Claude Code 에서 실제로 규칙대로 동작하는지는 **아직 검증하지 못했다**(이 환경에서는 스크립트·점검 모듈만 실행해 확인).
- 자동 점검은 명백한 실수(조인 부풀림, 결측, 기간 어긋남)만 잡는다. 집계 기준이 틀리는 것 같은 의미상 오류는 사람이 코드를 읽어야 한다 → 그래서 코드와 가정이 항상 기록에 남는다.
